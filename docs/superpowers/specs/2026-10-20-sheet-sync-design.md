# Google スプレッドシート連携（複数人での同時入力）計画

## Context
AniRetake（単一 index.html の PWA、データは各自のブラウザ内）を、複数の制作進行が同じ作品・話数を入力できるようにしたい。
ユーザー確定事項：連携先は Google スプレッドシート／目的は「複数人でアプリを使う」／第1段は文字の項目だけ共有し、参考画像は各自のブラウザに置く（画像の共有は第2段で Google ドライブ対応を別途計画）。
GAS へ丸ごと移植する案は採らない（オフライン・速さ・画像・クリップボードを失い、ほぼ作り直しになるため）。アプリは今のまま、シートを「みんなの共有の置き場」にして同期する。

## 開発の進め方（ユーザー指定）
- すべて `feature/sheet-sync` ブランチで行う。実際に使えると確認できるまで main（＝GitHub Pages 公開版 v2.0.3）には入れない。PR も作らない（リポジトリのルール）。
- 試すときは、ブランチの index.html をダウンロードしてダブルクリックで開く（保存先が公開版と分かれるので、普段のデータに影響しない）。
- 版番号は開発中 `2.1.0-dev` とし、上部に「開発版」の札を出して公開版と見分けられるようにする。

## Step 0 の結果（2026-10-21 実施済み）
- Windows の Chrome で、index.html を直接開いた（file://）状態から GAS への GET・POST の両方が成功し、シートに書き込めた。
- 1回の通信は約1.9〜2.4秒。→ 1回の操作ごとに同期するのではなく、「入力が止まって3秒後にまとめて1回送る」設計で問題ない。30秒ごとの確認も十分間に合う。
- 未確認：Mac の Safari／Chrome、GitHub Pages（https）から開いた場合。仕組み上は同じく動く見込みなので、本実装の試用時にあわせて確認する（README に手順を入れる）。

## 方式
**Google Apps Script（GAS）の Web アプリを中継に使う。**
- 管理者が1回だけ：共有シートで「拡張機能 → Apps Script」にアプリが表示するスクリプトを貼り、ウェブアプリとしてデプロイ（実行ユーザー：自分／アクセス：全員）。URL と合言葉をメンバーに配る。
- メンバーは環境設定（⚙）に URL・合言葉・自分の名前を入れるだけ。Google ログイン・外部ライブラリは不要。
- 通信は `fetch` の GET と、`Content-Type: text/plain` の POST（事前確認リクエストを起こさない形）。file:// で開いた場合も動く見込みだが未確認 → Step 0 で実機確認。
- 合言葉が一致しない要求は GAS が拒否する。

## シートの形（作品・話数ごとに1タブ、タブ名 `作品コード_話数`）
- 1行目：作品コード・話数・「AniRetake 共有シート（ID列と更新列は触らないでください）」
- 2行目：見出し。列＝`ID(版)`・`ID(カット)`・既存 `tableLayout("template")`（index.html:8841付近）の全項目・`更新者`・`更新日時`。ID列は狭く灰色。
- 3行目以降：1版1行（`tableRows()` 8829 の順）。値の作り方は `buildTableXlsx` 内 `valOf`（撮入れは ● / R回数）と同じ。
- カットと版は既に変わらない ID（`newId("c")`/`newId("v")`、3652）を持っているので、これを行の鍵にする。
- 見出しが既存形式なので、このタブを xlsx で落として既存の「表を読み込む」でも読める。
- シートでの直接編集も可（ID 列のある行の項目セル）。シートで新しく足した行（ID 空）は、次の同期で新しい版として取り込み、ID を書き戻す。

## 同期の仕組み（項目単位の「元の値つき書き込み」）
各アプリは話数ごとに「最後にシートと一致していた値（基準）」を版ID×項目で持つ（IndexedDB）。
- **送る**：基準と違う項目だけを `{版ID, 項目, 元の値, 新しい値}` で送る。GAS は `LockService` で順番待ちし、セルが「元の値」のままなら書き込む。違っていれば（他の人が先に直した）書かずに「衝突」として返す。新しい版は行を追加、削除した版は行を消す（その行が基準から変わっていなければ）。
- **受け取る**：GAS はタブを書き換えるたびに版番号（ScriptProperties）を1つ上げる。アプリは `?rev=前回の番号` で問い合わせ、変わっていなければ短い応答だけ返る。変わっていれば全行を受け取り、基準と違う項目を手元に反映（自分も未送信で直していた項目は衝突扱い）。行が消えていたら手元の版も消す（手元で未送信の変更があれば衝突扱い）。反映は既存の `TCOLS[k].set`（7777〜）を使い、兼用の自動記入・カット番号の桁そろえも今と同じに動かす。
- **衝突**：同じ版の同じ項目を2人が直したときだけ一覧を出し、項目ごとに「シートの値／自分の値」を選ぶ。選ぶまで他の項目の同期は続ける。
- **タイミング**：入力が止まって3秒後に送信→受信、画面を開いている間は30秒ごとに受信確認、画面に戻ったとき・手動の「今すぐ同期」。オフラインや失敗は「未送信 N件」と表示し、つながったら再送。`saveBlocked` のときは同期しない。
- 1人あたり30秒ごとの確認は8時間で約1,000回。GAS の1日の上限（無料アカウントで数万回規模とされるが要確認）に対して余裕はある見込み。

## アプリ側の変更（index.html）
1. 環境設定（⚙）に「スプレッドシート共有」欄：URL・合言葉・自分の名前・「スクリプトをコピー」・「接続テスト」・手順説明。全話数共通の prefs に保存。
2. 話数ごとの「この話数を共有する」切り替え。「話数 ▾」に「共有シートから話数を開く」（シートのタブ一覧から選ぶと、その作品・話数を手元に作って取り込む）。
3. 上部の保存状態の横に共有の状態：「共有：最新 12:34／送信中／未送信 3件／衝突 2件／オフライン」。衝突を押すと選択画面。
4. 一覧入力と「出力・保存」に「今すぐ同期」「シートを開く」。一覧入力の行に、最後に直した人（更新者）を薄く表示。
5. 共有していない話数・未設定時の動きは今と全く同じ（既存ユーザーに影響なし）。
6. ヘルプ文・README・CHANGELOG を更新し、版を v2.1.0 に。

コードは `// ===================== v2.1.0 スプレッドシート共有 =====================` の区画として、表の読み込み／書き出し区画（7553〜9340付近）の後ろにまとめ、`initTableIO()` と同じ形の `initSheetSync()` で初期化する。行データの作成は xlsx 書き出しと関数を共用する形に切り出す。

## GAS スクリプト（アプリ内に文字列で持ち、コピーして使う）
- `doGet`：`ping`（接続テスト）／`tabs`（タブ一覧）／`rows&tab&rev`（変わっていれば全行と版番号）。
- `doPost`：`{key, tab, user, ops:[追加/項目の書き込み/削除]}` → ロックして元の値を確認しながら適用、結果（成功・衝突・新しい版番号・書き戻した ID）を返す。タブが無ければ見出しつきで作る。

## 確認方法
- GAS と同じ応答をする小さなローカルの模擬サーバー（Node.js、メモリ上の表）を作り、Playwright の Chromium で index.html を**2つ同時に**開いて：
  - A で入力 → 数秒後に B に出る／A と B が別の項目を直す → 両方残る／同じ項目を直す → 後の人に衝突画面／A がカットを削除 → B からも消える／オフライン中の入力 → 復帰後に送られる／シート（模擬）側で直接直す → 両方に反映。
- xlsx 書き出しを切り出し前後で比べ、読み込みで「変化なし」になること。
- 本物の Google シートでの最終確認は手順書を渡してユーザーに依頼（こちらからは Google にログインできないため）。

## 弱点・注意（ユーザーに伝える）
- 画像は共有されない（第1段）。PNG を書き出す人が画像を持っている必要がある。
- シートに独自の列を足しても同期は壊れないが、アプリには入らない。ID 列・見出しは触らない。
- 「アクセス：全員」の Web アプリなので、URL と合言葉は社外に出さない。
- 反映は数秒〜30秒遅れ（同時編集の Google スプレッドシートほどの即時性はない）。
- 工程名・日付など話数の設定は共有しない（第1段）。

## 実装メモ（2026-10-21・第1段の試用版）
- 計画との違い：
  - 行データは xlsx 書き出しの関数を切り出さず、既存の列定義 `TCOLS` の get/set をそのまま使った（xlsx 書き出しには手を入れていない）。撮入れは1列（「セル・BG(R2)」の形）
  - GAS の「版番号」は使わず、シートの中身のハッシュで「変わっていない」を判定した（シートを手で直したときも検知できるように）
  - 共有の設定（URL・合言葉・名前・共有中の話数）は localStorage の `retake.sheet` に置き、JSON 保存には入れない。同期の基準は IndexedDB の `sheet:話数id`
  - 共有中の話数を JSON 読込で置き換えると、その話数の共有をやめる（古い内容で他の人の新しい変更を上書きしないため）
  - 一覧入力の表に「最後に直した人」を出す表示は未実装（衝突の画面にだけ出す）
- 送らないもの：参考画像、工程・日付、チェックしていない撮入れ素材の R 回数、選んでいない撮影の種類のテイク番号
- テスト：`experimental/sheet-sync/test-sync.mjs`（埋め込みの Apps Script を模擬サーバーで動かし、2人同時に試す。11項目）
