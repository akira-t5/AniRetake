# スプレッドシート共有 試用手順（開発版 v2.1.0-dev）

`feature/sheet-sync` ブランチの開発版を試すための手順です。公開版（GitHub Pages・v2.0.3）には入っていません。Windows・Mac どちらでも同じ手順です。

## 0. 大事なこと

- 開発版は **ブランチの index.html をダウンロードしてダブルクリックで開く** 形で使います。手元のファイルとして開くと、ブラウザ内の保存先が公開版と別になるので、普段のデータには影響しません。
- 普段の作業データでは試さないでください。テスト用の作品コード（例：`TST`）を使ってください。
- 1人で2人分を試すときは、**別のブラウザ**（例：Chrome と Edge）か、Chrome の **別のプロファイル** で開いてください。同じブラウザの別タブだと、同じ人として扱われます。

## 1. 開発版を手に入れる

1. GitHub で `akira-t5/AniRetake` を開き、ブランチを `feature/sheet-sync` に切り替える
2. `index.html` を開き、右上の「Download raw file」（↓のアイコン）で保存する
3. 保存した `index.html` をダブルクリックで開く。上部に **v2.1.0-dev 開発版** と出ていれば OK

## 2. 共有シートを用意する（1回だけ・シートを用意する人）

前回の通信テスト用シートとは別に、新しいスプレッドシートを作るのがおすすめです。

1. Google スプレッドシートを新しく作る（例：`AniRetake共有テスト`）
2. 「拡張機能」→「Apps Script」を開き、最初から入っている中身を全部消す
3. 開発版の AniRetake で ⚙（環境設定）→「スプレッドシート共有（開発中）」→「スクリプトをコピー」を押し、Apps Script に貼り付ける
4. 1行目近くの `const KEY = "ここに合言葉";` を好きな合言葉に変えて 💾 保存。**KEY を変えてからデプロイしてください。デプロイしたあとに直したときは、下の「新バージョン」での更新が必要です**（しないと「合言葉が違います」と出ます）
5. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
6. 「デプロイ」→ 承認（「Google で確認されていません」→「詳細」→「移動」→「許可」）
7. 表示された URL（…/exec）をコピー

※ スクリプトを新しいものに貼り替えたときは、「デプロイ」→「デプロイを管理」→ ✏（編集）→ バージョン「新バージョン」→「デプロイ」で更新します（URL は変わりません）。

## 3. 1人目（A）：話数を共有する

1. 開発版の AniRetake で ⚙ →「スプレッドシート共有」に URL・合言葉・自分の名前を入れる
2. 「接続テスト」→「つながりました」と出るか
3. 作品コード `TST`、話数 `01` にして、カットを3〜4個入れる（リテイク内容・修正内容・済なども）
4. ⚙ →「この話数を共有する」→ 確認で OK
5. シートに「TST_01」タブができ、1版1行で入っているか。上部に「共有：最新 時:分」と出ているか

## 4. 2人目（B）：共有された話数を開く

別のブラウザ（またはプロファイル）で開発版を開き、

1. ⚙ に同じ URL・合言葉と、別の名前を入れる
2. 「話数 ▾」→「共有シートから話数を開く」→「TST_01」を選ぶ
3. A と同じカットが入るか

## 5. チェックリスト

結果を ✓／✗ で教えてください。✗ のときは、そのとき出ていた画面の文字（上部の「共有：…」の札や、お知らせ）も一緒に。

| # | やること | 期待する結果 | 結果 |
|---|---|---|---|
| 1 | A でリテイク内容を直し、5秒待つ | シートのそのセルが変わる。更新者が A の名前になる | |
| 2 | 1 のあと B で「出力・保存」→「今すぐ同期」（または30秒待つ） | B に A の変更が入る | |
| 3 | 同じカットで、A は備考、B は修正内容を直す → 両方で今すぐ同期を2回ずつ | A・B とも両方の変更が入る（衝突にならない） | |
| 4 | 同じカットの同じ項目（リテイク内容）を A・B で別々に直す → A、B の順に今すぐ同期 | B の上部に「共有：衝突 1件」。押すと選択画面が出る | |
| 5 | 4 の選択画面で「自分」を選ぶ | シートと A が B の値になる | |
| 6 | A でカットを1つ削除 → 両方で同期 | シートと B からも消える | |
| 7 | シートで直接、あるカットの備考を書き換える → 両方で同期 | A・B に入る | |
| 8 | シートの一番下に手で行を足す（カット・リテイク内容・R を入れる。A・B 列は空のまま）→ 両方で同期 | A・B に新しいカットが1つずつ入り、シートの A・B 列に ID が入る | |
| 9 | カット番号 `001`、リテイク日、`=` で始まるリテイク内容を入れて送る | シートで `001` が `1` にならない、日付・`=` で始まる文がそのまま | |
| 10 | Wi-Fi を切って A で直す → 上部の札 → Wi-Fi を戻して同期 | 「未送信」→ つながると送られて B に届く | |
| 11 | B でリテイク内容を入力している最中に、A が同じカットを直して同期 | B の入力中の欄は書き換わらない。入力欄から出たあとの同期で入る | |
| 12 | 開発版を閉じて開き直す | 続きから同期でき、行やカットが増えない | |
| 13 | （Mac があれば）Mac の Safari／Chrome で 3〜5 を試す | Windows と同じく動く | |

## 6. わかっていること（今の版の制限）

- 参考画像は共有しません（第2段で Google ドライブ対応を検討）。PNG を書き出す人が画像を持っている必要があります
- 工程の名前・日付など話数の設定は共有しません
- 撮入れの R 回数（チェックしていない素材の分）と、選んでいない撮影の種類のテイク番号は共有しません
- 1回の同期は2〜5秒ほどかかります。他の人の変更が届くのは最大30秒ほど遅れます
- シートに独自の列を足しても同期は壊れませんが、アプリには入りません。A・B 列（ID）と2行目の見出しは変えないでください
- 一覧入力の表に「最後に直した人」を出す表示は、まだ入れていません

## 開発者向け

- 模擬サーバー：`node experimental/sheet-sync/mock-gas-server.mjs`（index.html に埋め込んだ Apps Script をそのまま Node.js で動かす）
- 2人同時のテスト：`node experimental/sheet-sync/test-sync.mjs`（Playwright が必要）
